## Fixed defects

- **Windows stale-upload cleanup:** `os.getuid()` does not exist on Windows. The POSIX process probe is also inappropriate there. Cleanup now uses a query-only Windows process handle, preserves live/inaccessible processes, and rejects symlinks/junctions. A real temporary-folder regression checks current-process preservation and dead-process cleanup.
- **Mixed-resolution distance calibration:** focal lengths from different image resolutions were averaged in pixel units and paired with the last resolution. Each sample is now normalized by its frame height before the median, then converted to the reference resolution. Corrupt calibration files safely disable estimates; nonfinite/negative calibration inputs are rejected; zero-height/reversed boxes produce no estimate.
- **Disconnected camera preview:** the OpenCV preview dereferenced `state.capture.finished` even when capture was `None`. It now tolerates camera reconnection periods. The regression simulates a disconnected camera and normal quit.
- **Pause/stop during paced video waits:** capture now checks pause/stop again after its frame timer, avoiding an extra decode after a request received during the wait.

Test portability corrections: Windows without Developer Mode can run demo-library functional tests without constructing a privileged symlink fixture. Symlink creation itself is not covered in that environment. The video-cleanup test now waits for asynchronous disposal, rather than treating the immediately reported queued source as proof that the old capture has already closed.

## Recognition and physical range: not verified

This branch requires classes **Escalator, People, Pillar, Stair, Wet Floor Sign**, in that order. It is a different taxonomy and dataset from the previous local chair-based checkpoint.

Git trees of all three branches contain no model files. `.gitignore` excludes `*.pt`, `*.pth`, and ONNX exports. The three downloaded main-branch ZIPs also contain no `.pt`/`.pth` files. Required assets are:

- `models/local/yolov8n_v4.pt`
- `models/cloud/rfdetr-nano_v4.pth`

The existing local chair-based model was deliberately not substituted or relabelled: that would produce invalid class IDs and misleading accuracy claims. Fresh end-to-end trained recognition on uploads therefore remains untested. Config/notebook scores are historical, not results of this review.

Maximum reliable distance in metres also remains unmeasured. It needs the actual checkpoint, the intended camera/zoom, and footage with tape-measured distances and complete object labels, ideally across sites and lighting conditions. Smaller bounding boxes or digitally scaled pictures are size stress tests, not physical-range measurements. The uncalibrated alert gate uses relative image size and is separate from whether the detector recognizes an object.

Next concrete step once matching weights are supplied: verify model class order, run the included golden images, exercise image and video uploads with the real detector, and record per-class matches/false positives and recall by object size. Follow `DISTANCE_TEST_SHEET.md` for measured physical-range trials. Do not claim a maximum metre range from the calibration maths alone.
